# F64A C2 paired BCa spread interval: development stop

On 2026-10-04 the separately frozen [BCa specification](f64a_c2_paired_interval_bca_v1.json), SHA-256 `55f1155c5fc08a88e929f53c60a17d3cbadc4c92ca2da7b90fd797a0da3ffb0f`, was tested on **development data only**. Its [runner](../src/analysis/f64a_c2_paired_interval_bca.py), SHA-256 `567242c1e6aecfb3af8caa12370253a37504e774302b101b7cb5b22a9ef0789c`, resamples complete pair rows, applies a jackknife acceleration correction to the late-SD contrast, and retains the paired movement Student-t interval. The base synthetic distribution and runner are pinned by hash. No SCC access or GPU job occurred.

With 200 development trials per scenario and 799 bootstrap draws per available interval, BCa spread coverage was only **83.5–85.9%** in the four 10-pair complete/MCAR scenarios, against the frozen 92% screen. It was 89.5–92.5% in the four 33-pair scenarios. These development results are in [development.json](../results/cpu_calibration/f64a_c2_paired_interval_bca_v1/development.json), SHA-256 `ee8e37edbb4990dfcebe736c72584bb5cd49a6c3f86b03a320a47e6a060f6824`.

Because the small-pair development screen failed substantially, **the reserved BCa held-out cohort was not run**. No BCa interval is selected for C2. An additional exploratory development-only paired basic-bootstrap check also fell below the 92% target in multiple cases; it was not promoted to a frozen held-out candidate. The prior [percentile-bootstrap result](f64a_c2_paired_interval_stress_result.md) likewise fails small-pair spread coverage. A final spread interval and pair count remain open scientific design decisions; no production inference follows.
